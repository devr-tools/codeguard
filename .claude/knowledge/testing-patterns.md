# Testing Patterns

Testing strategies, test infrastructure quirks, how to run/debug specific test suites, mocking conventions.

- **Trust policy is process-global.** `tests/checks` and `tests/codeguard` have a `TestMain` (`trust_main_test.go`) that enables config commands and loopback AI endpoints. A new package that runs config commands or hits a `127.0.0.1` server needs one too, or it fails with "refusing to run config-supplied command" or "ssrf guard". `tests/security` deliberately has none: it tests the secure default and sets policy per test with `trust.Set` + `t.Cleanup(trust.ResetFromEnv)`.
- **New tests go under `tests/` as external `_test` packages.** The self-scan will NOT catch a violation, because `.codeguard/codeguard.yaml` allows `internal/**` and `cmd/**` for legacy in-package tests. Enforcement is by review. Prefer testing through exported API; extend an existing in-package test only if you truly need unexported access.
- **Never commit a contiguous real-format secret.** GitHub push protection rejects it, even in `_test.go`. Build fixtures at runtime with `cred(prefix, body)` (`tests/checks/test_helpers_test.go`) or a split literal (`"AKIA" + "..."`, joined by `foldConcatenatedLiterals`). Vendor placeholders like `AKIAIOSFODNN7EXAMPLE` belong in corpus `clean/` fixtures, never `vulnerable/` ones.
- **Rule catalog tests:** every rule needs a `FixTemplate` with a valid `Kind` (`catalog_fix_templates_*.go`). `security.*` rules need an OWASP mapping (`catalog_security_owasp.go`) and a CWE. Every emitted rule id must be in the catalog (`TestEveryEmittedRuleIDIsInTheCatalog`). Catalog examples are scan-verified (`tests/rules/examples_test.go`). Every rule needs a row with an anchor in `docs/rule-index.md`, and every config key must be documented (`tests/rules/docs_coverage_test.go`).
- **The corpus** (`tests/corpus/`): fixtures go in `testdata/<group>/<rule>/{vulnerable,clean}/`, with `expectations.yaml`. A `known_gaps` entry fails on purpose once the gap is fixed, so update the manifest in the same change. The corpus covers the security section only; other sections rely on hand-written fixtures.
- **MCP tests drive the real binary in a subprocess**: a helper-process test gated by `GO_WANT_MCP_HELPER_PROCESS` (stdio) or `GO_WANT_MCP_HTTP_HELPER_PROCESS` (HTTP) re-execs `os.Args[0]`. The HTTP config comes from `CODEGUARD_TEST_HTTP_CONFIG`. For server→client tests (`sampling_test.go`), wait for the SSE `: ready` comment before expecting requests.
- **The Node semantic engine can hijack TS tests** on hosts with a discoverable `typescript.js` (e.g. VS Code installed). To force the per-file Go path, set `CODEGUARD_TYPESCRIPT_LIB_PATH` to an existing but invalid lib.
- Defensive-rule positive fixtures must avoid UI-style names (`render*`): those contexts are intentionally skipped. Precision retunes need both the FP fixture and a nearby positive that still fires.
- **For rules that can fire en masse, assert the exact message set**, not just that the rule fired (`assertFindingRulePresent`). Pin both directions of "stay silent when unsure": a garbage input yields zero findings, and a valid empty input still reports.
- **The no-config scan path** can only be tested from a directory with no discoverable config: config resolves from the cwd (`./codeguard.yaml`, `./.codeguard/`), not the scanned folder. Inside this repo it silently uses the self-scan config.
- **For real-repo FP sweeps**, use an absolute `targets[].path`, because a relative path resolves against the config file's directory. Set `cache.enabled: false` and use `--format json`.
- **Measure on a frozen tree**, because a live tree changes between runs. Use `git archive HEAD | tar -x -C <dir>` for the tracked tree. For exclusion, budget or memory work, use `rsync -a --exclude .git` + `chmod -R a-w` instead: archive omits the gitignored build output those mechanisms prune (one repo: 643 vs 37,486 files). If a `*-budget` diagnostic fires, findings are truncated, so run 3× and report the spread. For TS targets, measure memory including the `node` semantic child process, which dominates.
- **When A/B-ing two branches for a findings delta**, build both from the same merge base and change one thing. Otherwise unrelated work gets credited to your fix.
- **Checking whether a self-scan added findings:** `make codeguard-ci` prints only counts. Diff the `N. at:` lines against a clean worktree at HEAD. `quality.ai.narrative-comment` fires on "what"-style doc comments.
- Before blaming your change for a `tests/checks` failure, reproduce a baseline in a clean worktree (`git worktree add --detach <dir> HEAD`). Under `-race`, the full suite needs `-timeout 60m`.
- Parallel agents share the session scratchpad and will clobber each other's generic filenames (`commitmsg.txt`, `lint.sh`). Namespace every scratch file by branch or agent id.
